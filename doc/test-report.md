## 3. 发现的问题

### 3.1 Token 频繁过期 (低优先级)

**现象**: 在测试过程中，会话多次因 Token 过期被重定向到登录页面。

**影响**: 用户需频繁重新登录，影响使用体验。

**建议**:
- 检查 Token 有效期配置（当前疑似较短）
- 确认 Token 自动刷新机制是否在所有场景下生效（页面空闲时间较长后恢复操作）

### 3.2 用户角色显示为 "userRole.undefined" (中优先级)

**现象**: 用户列表中"角色"列显示为 `userRole.undefined`，而非实际角色名称。

**影响**: 管理员无法直观了解用户角色分配情况。

**建议**: 检查角色字段的 i18n key 映射或后端返回值。

### 3.3 n8n iframe 交互受限 (低优先级)

**现象**: n8n 通过 iframe 嵌入，受同源策略限制，自动化测试无法直接操作 n8n 内部元素。

**影响**: 仅影响自动化测试，用户手动操作不受影响。

**建议**: 这是预期行为，可通过"新窗口打开"直接使用 n8n。

### 3.4 Agent 执行历史 "Unknown Subject" (低优先级)

**现象**: Agent 执行时间线中 #32 工单显示 "Ticket #32 – Unknown Subject"，但实际工单标题为 "Info."。

**影响**: 执行历史中无法快速识别工单。

**建议**: 检查本地 IndexedDB 记录中 subject 字段是否正确传入。

## 4. 总结

### 4.1 系统整体质量评估

FD-AutoPilot v0.4 系统整体功能完整，核心业务流程（工单管理、Agent 自动化、权限管理、任务调度）均可正常使用。

**亮点**:
- 工单分栏对比视图，原文+翻译对照清晰
- Agent 执行日志结构化元数据，调试体验好
- Capability 体系设计完善，Agent 管理灵活
- 任务仪表盘信息丰富（SyncBridge/断路器/路由统计）
- 数据库管理直接 SQL 查询，运维效率高

**待改进**:
- Token 刷新机制在长时间空闲后可能失效
- 用户角色显示 i18n 映射缺失
- 本地执行历史 subject 字段填充不完整

### 4.2 建议优先处理项

1. **[中]** 修复用户列表角色列 `userRole.undefined` 显示问题
2. **[低]** 优化 Token 过期刷新策略
3. **[低]** 执行历史 subject 字段完善
4. **[建议]** 清理代码中的无用模块和死代码（workflow 模块已删除但可能有残留引用）
