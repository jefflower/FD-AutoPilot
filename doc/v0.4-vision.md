# FD-AutoPilot v0.4 — 版本目标与实现状态

## 系统定位

**FD-AutoPilot** — Agent 驱动的工作流自动化平台。n8n 作为唯一编排引擎，通过 Sync Bridge 调用客户端 Agent 实现业务自动化。工单处理（Ticket）是第一个业务模块，平台级基础设施（认证、任务调度、AI Agent、Sync Bridge）可复用于后续业务模块。

## v0.4 核心架构

### 三层模型：Capability → Agent → n8n

```
┌─────────────────────────────────────────────────────────────────┐
│  n8n 编排层                                                      │
│  定时/Webhook → HTTP Request → capability + 业务参数             │
│  例: POST /api/v1/n8n/capabilities/ticket-translate/execute      │
│  n8n 不关心具体用哪个 Agent，只声明业务意图                        │
│  可选: targetClientId / targetUserId 指定执行客户端              │
└──────────────────────────┬──────────────────────────────────────┘
                           │ 服务端路由：查找可用 Agent + Client
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│  Agent 层（业务语义）                                             │
│  AgentDefinition: promptTemplate + inputSchema + outputSchema    │
│  AgentInstance: 每设备运行实例（本地配置覆盖 + 运行状态）          │
│  同一 capability 可有多个 Agent 实现（如 ticket-translate 用       │
│  gemini-cli，ticket-translate-claude 用 claude-cli），服务端路由   │
└──────────────────────────┬──────────────────────────────────────┘
                           │ 绑定 requiredCapability
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│  Capability 层（执行能力）                                        │
│  当前: gemini-cli, claude-cli, notebooklm-py                     │
│  预留: shadow-window（通用网页 RPA，可操控任意网页）               │
│  每个能力: 环境检测 + 安装引导 + 开关控制 + 健康检查              │
└─────────────────────────────────────────────────────────────────┘
```

### 6 模块后端

```
fd-server/
├── fd-server-common/       公共基础（DTO、工具类、异常处理）
├── fd-server-auth/         认证授权（JWT、RBAC、OAuth、组织同步）
├── fd-server-task/         任务调度（多客户端分发、定时任务、SSE、超时回收）
├── fd-server-ai/           AI Agent（定义/实例/绑定/SyncBridge/Capability）
├── fd-server-ticket/       工单业务（Freshdesk 集成、通知、n8n 集成）
└── fd-server-app/          启动入口 + n8n Agent 控制器
```

依赖链：`common ← auth ← task ← ai ← ticket ← app`

### Capability 层

Capability 是客户端可提供的 AI 执行能力，作为一等概念管理：

| Capability | 环境 | 描述 | 状态 |
|-----------|------|------|------|
| gemini-cli | Tauri/Bridge | Google Gemini CLI 命令行工具 | 当前 |
| claude-cli | Tauri/Bridge | Anthropic Claude CLI 命令行工具 | 当前 |
| notebooklm-py | Tauri/Bridge | notebooklm-py Python 库 | 当前 |
| shadow-window | 仅 Tauri | 通用网页 RPA 自动化（可操控任意网页） | **预留** |

每个 Capability 具备：
- **用途说明** — 面向用户的功能描述
- **环境检测** — 自动检测是否可用（命令行工具是否安装、Python 包是否存在）
- **安装引导** — 不可用时引导用户安装（命令、链接、步骤说明）
- **开关控制** — 用户可在设置页面启用/禁用
- **健康检查** — 定期检测能力状态

**shadow-window 预留规划：** 类似 RPA 的通用网页自动化能力。目标是可以自动化操控任何网页，前端预留模块入口。当前的 NotebookLM Shadow Window 和 17track 物流查询是该能力的特化前身，未来统一到 shadow-window 框架下。

### Agent 层：Definition + Instance 分离

采用类似 K8s Deployment/Pod 的模型：

**AgentDefinition（全局定义，服务端存储，管理员管理）：**
- 业务身份：code, name, description, capability（业务意图，如 ticket-translate）
- 执行配置：promptTemplate, inputSchema, outputSchema
- 底层能力：requiredCapability（如 gemini-cli）
- 默认参数：defaultParams（JSON，可被 Instance 覆盖）
- 系统属性：enabled, builtIn, sortOrder

**AgentInstance（设备实例，服务端存储，clientId 隔离）：**
- 归属：clientId, userId, agentCode（→ AgentDefinition）
- 本地配置覆盖：localConfig（JSON，覆盖 Definition 默认参数）
- 运行状态：running, lastHeartbeat, version
- 客户端注册时自动创建，仅对应客户端可修改

**配置合并优先级：**
```
n8n 调用参数（最高） > AgentInstance.localConfig > AgentDefinition.defaultParams（最低）
```

### Capability 级路由（n8n 调用模型）

n8n 调用的是**业务意图**（capability），而非具体 Agent 实现：

```
n8n HTTP Request:
POST /api/v1/n8n/capabilities/ticket-translate/execute
{
  "ticketId": 123,
  "targetLang": "zh-CN",
  "clientId": "mac-zhang-01"    // 可选，不传则任意客户端
}
```

**服务端路由逻辑：**
1. 查找所有 capability = `ticket-translate` 的 AgentDefinition
2. 查找有对应 AgentInstance 且在线的客户端
3. 如果指定了 clientId，过滤到该客户端
4. 检查客户端是否启用了 Agent 所需的 Capability（如 gemini-cli）
5. 选择一个可用的 Agent + Client 组合
6. 通过 Sync Bridge 下发任务

**多 Agent 竞争同一 capability：**
- `ticket-translate`（requiredCapability: gemini-cli）和 `ticket-translate-claude`（requiredCapability: claude-cli）都绑定 `ticket-translate` capability
- 客户端 A 只装了 gemini-cli → 只能执行 ticket-translate
- 客户端 B 装了 claude-cli → 只能执行 ticket-translate-claude
- 客户端 C 两个都装了 → 服务端按优先级/负载选择

### 执行模型：Sync Bridge

```
n8n 定时/Webhook 触发
  → HTTP Request → POST /api/v1/n8n/capabilities/{capability}/execute
  → 可选参数: targetClientId / targetUserId
  → Pre-flight: 查找可用 Agent + 在线客户端
    → 无可用组合 → 立即返回 503（附原因）
  → SyncAgentExecutionService.executeSyncOnClient(agentCode, input, 5min)
    → 创建 TaskInstance（附 targetClientId 路由信息）
    → 注册 CompletableFuture
    → 前端 MQ Consumer claim（按路由匹配）→ Agent Executor 执行
    → POST /tasks/{id}/complete → SyncTaskCompletionListener
    → future.complete(result) → 返回 n8n
  → 超时 → 返回 504 + 清理 Future
```

**任务路由策略（可选）：**

| 路由方式 | 参数 | 行为 |
|----------|------|------|
| 默认 | 无 | 任意具备所需 Capability 的在线客户端 |
| 指定设备 | targetClientId | 仅该设备可 claim |
| 指定用户 | targetUserId | 该用户的任意在线设备可 claim |

### 客户端注册与心跳

客户端启动时向服务端注册：
1. 上报 clientId、userId、已启用的 Capability 列表
2. 服务端为每个 Agent 自动创建/更新 AgentInstance
3. 定期心跳保持在线状态
4. 服务端据此判断任务可路由的客户端

### 内置 Agent

**当前可用（v0.4）：**

| Code | Capability（意图） | RequiredCapability（底层） | 用途 |
|------|-------------------|--------------------------|------|
| ticket-translate | ticket-translate | gemini-cli | 工单翻译（含 systemPrompt 模板） |
| ticket-reply | ticket-reply | notebooklm-py | 工单回复（通过 notebooklm-py 知识库生成） |

Agent 命名原则：**以业务意图命名**（ticket-translate、ticket-reply），而非底层能力（gemini、notebooklm）。底层用什么能力取决于客户端配置。

| Context | taskType | 模式 | 用途 |
|---------|----------|------|------|
| MQTranslateAgentContext | agent.ticket-translate | serial(1) | Sync Bridge 工单翻译任务 |

### 工单状态流转（n8n 驱动）

```
PENDING_TRANS → TRANSLATING → PENDING_REPLY → REPLYING → PENDING_AUDIT → AUDITING → APPROVED → COMPLETED
```

审核分支：PASS → COMPLETED | REJECT → PENDING_REPLY（n8n 下次扫描拾取） | RETRANSLATE → PENDING_TRANS（n8n 下次扫描拾取）

n8n 通过 cron 定时扫描 `GET /api/v1/n8n/tickets/pending` 和 `GET /api/v1/n8n/tickets/pending-reply` 获取待处理工单，自然覆盖审核驳回循环。

### Agent 执行可视化

**本地执行记录：**
- 客户端本地存储 Agent 执行历史（IndexedDB / Tauri 文件系统）
- 记录：agentCode、输入摘要、输出摘要、耗时、状态、时间戳
- 时间线视图：可视化展示执行过程
- 仅本地存储，不上传服务端（保护隐私 + 减轻服务端负担）
- 服务端 AgentExecution 表保留统计级数据（成功/失败/耗时）

### 优雅失败

| 场景 | 行为 | 返回 |
|------|------|------|
| Capability 开关关闭 | 不 claim 任务 | Sync Bridge 超时 → 504 |
| 无客户端在线 | Pre-flight 检查 | 立即 503 + 原因说明 |
| 无 Agent 绑定该 capability | Pre-flight 检查 | 立即 404 + 原因说明 |
| 客户端执行失败 | Agent 返回错误 | complete(error) → n8n 收到错误 |
| 执行超时 | CompletableFuture 超时 | 504 + 任务状态清理 |
